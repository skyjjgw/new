# 使用与部署说明

## 数据链路

1. 边缘端从 USB 摄像头采集画面，并从 GNSS 获取位置；
2. YOLOv8 ONNX 在边缘端完成推理，生成遥测、障碍事件和可选快照；
3. 数据通过带令牌的 HTTP API 直接上传视桥自有云；
4. 识别画面由 FFmpeg 发布到 MediaMTX，浏览器通过 WHEP/WebRTC 播放；
5. 管理员审核上报并发布公共任务；志愿者在 App 地图或任务列表中接单；
6. 志愿者提交处理凭证，管理员复核后关闭事件。

## 配置边界

| 位置 | 应保存内容 | 是否提交 |
| --- | --- | --- |
| `*.env.example` | 变量名和无效占位值 | 是 |
| 本地 `.env` | 开发用真实配置 | 否 |
| `99_私密配置_禁止提交` | 本地密钥备份 | 否 |
| `/etc/visionbridge/*.env` | 服务器和边缘设备生产配置 | 否 |

至少应分别生成 API 登录签名密钥、边缘上传令牌、媒体发布密钥和 TURN 密钥，不要复用密码。

## 本地联调顺序

1. 在 `apps/dashboard` 启动 FastAPI；
2. 启动管理大屏并确认 `/api/v1/health` 正常；
3. 使用 `apps/volunteer` 的 Web 或 Android 调试版本连接同一 API；
4. 用示例或测试接口创建上报，验证审核、派单、接单、处理、复核状态流；
5. 最后接入真实边缘端遥测和 WebRTC 画面。

## 生产部署

`deploy/` 中的脚本用于现有 Ubuntu 自有云环境。执行前应：

- 配置 HTTPS 域名和有效证书；
- 在云防火墙和系统防火墙放行 Web、TURN 与 WebRTC 所需端口；
- 通过环境变量向部署脚本提供 SSH 凭据，禁止写入命令或仓库；
- 先备份数据库，再使用带校验值的发布归档；
- 部署后检查 API 健康、页面、App、WebRTC、TURN 中继和回滚路径。

详细脚本参数见 [deploy/README.md](../deploy/README.md)。
