# 盲道占用项目平台落地与可视化设计

## 1. 官方能力结论

- `IoT Edge` 官方文档明确说明：左侧 `站点链接` 可跳转到其他服务，且默认包含 `Dashboard`；如果从其他电脑访问，需要把站点链接里的 `127.0.0.1` 改成安装机 IP。
- 官方产品页明确列出 `Data visualisation`、`Alert Monitoring`、`Data Analysis` 能力，适合当前这个“边缘识别 + 云端告警 + 大屏展示”项目。
- 安装文档还说明试用期默认属性点上限为 `50` 点，因此属性设计不能无节制膨胀。

## 2. 当前建议

- 站点链接里真正要用起来的是：
  - `Dashboard`：做监管大屏、地图、趋势图、告警列表。
  - `Notification`：做事件通知和设备异常通知。
  - `LicenseAgent`：只管授权，不作为业务展示入口。
- 当前边端脚本已经控制在 `33` 个点位以内，仍在试用版 `50` 点预算内，可直接落地。

## 3. 当前已落地属性

当前脚本已开始上报以下属性，全部为 `int`，便于直接在 IoTSuite 设备模型中创建。

| 属性名 | 类型 | 含义 |
|---|---|---|
| `cameraStatusCode` | `int` | 摄像头状态：`0=init,1=streaming,2=read_failed` |
| `gpsStatusCode` | `int` | GPS 状态：`0=disconnected,1=ok,2=connecting,3=no_port,4=error` |
| `edgeStatusCode` | `int` | 边端状态：`0=init,1=running,2=alert,3=camera_error` |
| `alertLevelCode` | `int` | 告警等级：`0=normal,1=attention,2=warning,3=critical` |
| `obstacleTypeCode` | `int` | 事件类型：`0=none,1=non_motor_vehicle,2=motor_vehicle,3=construction_obstacle` |
| `rawObstacleClassCode` | `int` | 原始模型类别：`0=none,1=person,2=bicycle,3=motorcycle,4=obstacle_other,5=traffic_light_red,6=traffic_light_green,7=zebra_crossing` |
| `obstacleConfidence` | `int` | 置信度百分比 |
| `eventActive` | `int` | 当前是否处于事件上报态 |
| `eventCount` | `int` | 累计事件数 |
| `dailyEventCount` | `int` | 当日事件数 |
| `lastEventAgeSec` | `int` | 最近一次事件距今秒数 |
| `captureEpoch` | `int` | 本次上报时间戳（秒） |
| `gpsLatE6` | `int` | 纬度乘 `1e6` |
| `gpsLngE6` | `int` | 经度乘 `1e6` |
| `speedKmhX100` | `int` | 速度乘 `100` |
| `gpsAngleDegX100` | `int` | 航向角乘 `100` |
| `gpsAgeSec` | `int` | GPS 最近一次更新距今秒数 |
| `numSats` | `int` | 卫星数 |
| `hdopX100` | `int` | HDOP 乘 `100` |
| `altitudeCm` | `int` | 海拔厘米 |
| `roiOccupied` | `int` | ROI 是否被目标占用 |
| `detectionsInFrame` | `int` | 当前帧检测框总数 |
| `targetDetectionsInFrame` | `int` | 当前帧目标类且命中规则的数量 |
| `triggerStreak` | `int` | 连续触发帧计数 |
| `snapshotReady` | `int` | 是否已生成最近一次抓拍图 |
| `cameraFpsX100` | `int` | 实际采集帧率乘 `100` |
| `inferenceMs` | `int` | 单次推理耗时 |
| `cameraWidth` | `int` | 当前摄像头采集宽度 |
| `cameraHeight` | `int` | 当前摄像头采集高度 |
| `pointCode` | `int` | 点位编码，当前固定 `1` |
| `deviceSourceCode` | `int` | 设备来源编码，当前 `1=usb_camera+lc76g` |
| `modelVersionCode` | `int` | 模型版本编码，当前固定 `1` |

系统模块还需保留：

| 模块 | 属性名 | 类型 | 含义 |
|---|---|---|---|
| `#SYS` | `deviceStatus` | `string` | 设备在线状态 |

## 4. 设备模型创建建议

在设备模型 `defaultModule` 中创建上表全部属性，不需要再拆第二个业务模块。

原因：

- 当前平台属性编辑页对 `int` 更稳定。
- `Dashboard`、`Notification`、规则判断都更适合直接消费整型点位。
- 后续如果平台确认可以稳定支持 `string/double`，再补原始语义字段，不影响当前演示闭环。

## 5. Dashboard 设计

建议在 `站点链接 -> Dashboard` 中做 5 个区块。

### 5.1 顶部状态卡

- 设备在线状态：`#SYS.deviceStatus`
- 摄像头状态：`cameraStatusCode`
- GPS 状态：`gpsStatusCode`
- 当前告警等级：`alertLevelCode`
- 当日事件数：`dailyEventCount`

### 5.2 地图/GIS 区块

- 点位坐标来源：`gpsLatE6`、`gpsLngE6`
- 弹窗建议展示：
  - `obstacleTypeCode`
  - `obstacleConfidence`
  - `lastEventAgeSec`
  - `numSats`
  - `cameraFpsX100`

说明：

- 平台若不支持直接除法换算，可先展示整数坐标；若支持表达式，则将 `gpsLatE6 / 1e6`、`gpsLngE6 / 1e6` 转回真实经纬度。

### 5.3 趋势监控区块

- 摄像头帧率趋势：`cameraFpsX100`
- 推理耗时趋势：`inferenceMs`
- 卫星数趋势：`numSats`
- HDOP 趋势：`hdopX100`

### 5.4 告警事件区块

- 当前是否告警：`eventActive`
- 事件类型：`obstacleTypeCode`
- 置信度：`obstacleConfidence`
- 连续触发帧：`triggerStreak`
- 是否已抓拍：`snapshotReady`

### 5.5 调试诊断区块

- 当前检测框总数：`detectionsInFrame`
- 目标检测框数：`targetDetectionsInFrame`
- 原始模型类别：`rawObstacleClassCode`
- 摄像头分辨率：`cameraWidth`、`cameraHeight`
- GPS 数据新鲜度：`gpsAgeSec`

## 6. Notification 设计

建议在 `站点链接 -> Notification` 至少建 4 类通知。

### 6.1 占道事件通知

- 触发条件：
  - `eventActive == 1`
- 通知内容建议包含：
  - 点位
  - 事件类型
  - 置信度
  - 经纬度

### 6.2 摄像头故障通知

- 触发条件：
  - `cameraStatusCode != 1`

### 6.3 GPS 异常通知

- 触发条件：
  - `gpsStatusCode != 1`
  - 或 `gpsAgeSec > 30`

### 6.4 性能退化通知

- 触发条件：
  - `inferenceMs > 1200`
  - 或 `cameraFpsX100 < 500`

## 7. 预览框显示说明

当前边端网页预览已改为显示检测框：

- 蓝色/青色：模型识别到了，但不一定是当前要触发治理的目标。
- 橙红色：属于治理目标，且命中了 ROI 判定。
- 标签内容：
  - 类别名
  - 置信度
  - 是否命中 `ROI`

因此后续你看网页预览时，可以直接判断：

- 模型有没有识别到；
- 识别类别对不对；
- 为什么有框但没有触发事件；
- 是不是落在 ROI 外面。

## 8. 当前工程结论

- 现在这套边端已经具备：
  - 实时预览
  - 检测框显示
  - 事件去重
  - GPS 融合
  - MQTT 上报
  - Dashboard/Notification 可消费属性
- 下一步不需要先换模型，可以先把：
  - 设备模型属性创建
  - Dashboard 页面
  - Notification 规则
  三件事做完，形成完整演示闭环。
