# 盲道占用项目云端参数设计

## 1. 推荐云端对象

- 设备模型：`BlindWayOccupancyGatewayModel01`
- 网关设备：`blindway-gateway-01`
- 模块名：`defaultModule`
- 系统模块：`#SYS`

说明：

- 这条项目链路继续使用已经验证过的原生 MQTT 协议：
  - 上报：`/device/{gatewayId}/up/report`
  - 心跳：`/device/{gatewayId}/up/heartbeat`
- `#SYS.deviceStatus` 必须保留，否则设备在线状态不稳定。

## 2. 云端参数表

当前 IoTSuite 这个设备模型编辑页实际可稳定创建的属性类型是**整数族**，因此项目落地时采用“边端编码、云端整型展示”的方案。建议在 `defaultModule` 下创建这些属性。

| 属性名 | 数据类型 | 示例 | 含义 |
|---|---|---:|---|
| `cameraStatusCode` | `int` | `1` | 摄像头状态：`0=init, 1=streaming, 2=read_failed` |
| `gpsStatusCode` | `int` | `1` | GPS 状态：`0=disconnected, 1=ok, 2=connecting, 3=no_port, 4=error` |
| `edgeStatusCode` | `int` | `1` | 边端状态：`0=init, 1=running, 2=alert, 3=camera_error` |
| `obstacleTypeCode` | `int` | `1` | 占道类型：`0=none, 1=non_motor_vehicle, 2=motor_vehicle, 3=construction_obstacle` |
| `obstacleConfidence` | `int` | `86` | 置信度百分比 |
| `eventActive` | `int` | `1` | 当前是否触发告警 |
| `eventCount` | `int` | `12` | 累计事件数 |
| `dailyEventCount` | `int` | `5` | 当日事件数 |
| `captureEpoch` | `int` | `1783145530` | 最近一次上报时间戳（秒） |
| `gpsLatE6` | `int` | `28632112` | 纬度乘以 `1e6` |
| `gpsLngE6` | `int` | `121138923` | 经度乘以 `1e6` |
| `speedKmhX100` | `int` | `74` | 速度乘以 `100` |
| `numSats` | `int` | `19` | 卫星数 |
| `hdopX100` | `int` | `93` | HDOP 乘以 `100` |
| `altitudeCm` | `int` | `927` | 海拔乘以 `100`，单位厘米 |
| `roiOccupied` | `int` | `1` | ROI 是否被占用 |
| `cameraFpsX100` | `int` | `1250` | 帧率乘以 `100` |
| `inferenceMs` | `int` | `98` | 单次推理耗时 |
| `pointCode` | `int` | `1` | 点位编码，当前固定为 `1` |
| `deviceSourceCode` | `int` | `1` | 设备来源编码，当前 `1=usb_camera+lc76g` |
| `modelVersionCode` | `int` | `1` | 模型版本编码，当前固定为 `1` |

系统模块必须包含：

| 模块 | 属性名 | 数据类型 | 示例 |
|---|---|---|---|
| `#SYS` | `deviceStatus` | `string` | `online` |

## 3. 事件类型映射

当前本地权重 `best.pt` 可解析的类别名如下：

- `person`
- `bicycle`
- `motorcycle`
- `obstacle_other`
- `traffic_light_red`
- `traffic_light_green`
- `zebra_crossing`

当前项目上云建议映射：

| 模型类别 | 项目事件类型 | 说明 |
|---|---|---|
| `bicycle` | `non_motor_vehicle` | 非机动车占道 |
| `motorcycle` | `motor_vehicle` | 两轮机动车占道 |
| `obstacle_other` | `construction_obstacle` | 杂物/施工物占道 |

注意：

- 你当前这版权重里**没有 `car` 类**。
- 如果答辩里要覆盖“四轮机动车违停”，后续需要补充带 `car`/`truck` 的训练集并重训。

## 6. 容易出问题的点

### 6.1 数据收集逻辑

- 摄像头只识别不等于告警，需要叠加 `ROI` 命中和连续帧确认。
- 同一障碍物不能每帧都报，需要 `cooldown` 去重。
- GPS 室内或遮挡时会抖动，必须保留平滑和跳点过滤。

### 6.2 发送逻辑

- `ts` 每次必须更新，否则云端会判重或只显示一次。
- `heartbeat` 和 `report` 需要同时保留。
- `#SYS.deviceStatus=online` 不能省。

### 6.3 网关发送逻辑

- 这条项目链路是边端设备直接拿 `DCCS KEY` 换 MQTT 凭据后上云。
- 不是本地 IoTEdge 转发链。
- 当前模型页受限于整数族数据类型，因此边端脚本已改成整数编码上报。
- 如果后面云端模型页放开 `string/double`，再回切为原始语义字段即可。
